## 差距的含义

| 条件 | 本地 Nr3D | 本地 ScanRefer |
| --- | --- | --- |
| 物体实例几何 | ScanNet GT 实例 | Mask3D 预测实例 |
| 推理类别 | 预测 Top-5 | 预测 Top-5 |
| 评分 | 目标 ID 准确率 | 预测框 Acc@0.25 / @0.5 |
| 已完成参考 | 历史全量69.66% | 开发96条58.33% / 52.08% |

“预测类别”不等于“预测实例几何”。Nr3D的干净实例前提避开了部分漏检、残缺、合并及框误差；但Nr3D也专门考查同类干扰物，不能说它没有实例辨别难度。[1–2]

历史全量和反复使用的96条开发样本不能严格排名。11.33个百分点是观察到的差值，不是已经被某一个原因解释的因果效应。

你提供的Nr3D r18单轮结果也已经表现出相同的薄弱处：Dep.62.10%低于Indep.73.78%（11.68点），Hard65.28%低于Easy74.34%（9.06点）。69.66%的Overall没有消除方向与同类辨别的困难。它支持检查这些能力是否在ScanRefer输入条件下进一步受影响，但不能据此声称ScanRefer的视角依赖比例更高；两个数据集的分组定义也不能直接对应。

## 本地证据按优先级排序

1. **同类实例辨别是最直接的损失位置。** ScanRefer Unique19/21=90.48%，Multiple37/75=49.33%。按归档的原运行类别池ID核对，86条含合格候选，其中选对56条、失败30条；30条中25条选框最佳匹配为同一规范类别的另一实例。另8条没有合格候选、2条解析或池记录不可用。旧后置重算的87条覆盖/31条有覆盖失败改变了q507的池，不作为原运行分母。框最佳匹配也不保证真实语义身份。[原池计数与限定](/Volumes/KESU/datasets/ScanRefer/literature_review_20261026/DECISION_COUNTS.json)
2. **描述理解与证据选择值得优先研究，但效应未定量。** 固定同23个场景、目标及Mask3D前端，用两个数据集各自原始描述实时解析并推理，Nr3D15/23、ScanRefer11/23@0.25；两边合格实际候选覆盖均21/23。一次小样本配对p=.125，只提供开发信号。轨迹出现将世界X当作left/right、缺失参照时自行替代、从句中的物体混入最终目标等问题；这不意味着每种现象都已证明是唯一错误原因。[同目标原文对照](/Volumes/KESU/datasets/ScanRefer/runs/r94_same_target_language23_v1/FINAL_DIAGNOSTIC.json)
3. **前端是额外风险，不能用文献差值直接解释本地差值。** 固定同32条Nr3D原文和旧解析，GT实例23/32、Mask3D22/32@0.25；@0.5为23/32对18/32。这改变了整个前端，包含实例集合、类别、框和检测分数，不是纯框消融。当前仅支持把前端框质量列为@0.5的重要诊断方向。[同语言前端对照](/Volumes/KESU/datasets/ScanRefer/runs/r93_instance_frontend_diagnostic32_v1/FINAL_DIAGNOSTIC.json)
4. **ScanRefer当前输入更复杂。** 实际旧输入中位数：对象目录85对40.5、目标候选11对5、参照候选9.5对3.5、首轮tokens约3.12万对1.49万。不同样本和场景混在一起，不能据此断言tokens或检测器导致准确率下降。无损压缩也未带来完整开发集收益。[输入审计](/Volumes/KESU/datasets/ScanRefer/literature_review_20261026/input_condition_audit.json)

ScanRefer采集要求至少两句，描述外观和相对位置；ReferIt3D强调在同类干扰物中沟通目标。多句带来更多指代、从句归属和关系组合，但信息也可能帮助定位。ScanRefer附录Table11中，完整描述相对首句的Overall @0.5为27.40对26.12，@0.25则为41.19对41.44：不能说完整描述在两个阈值均更好，也不能由本地分差推导应自动截短查询。[1–2]

## 应怎样改，以及怎样证明有效

优先处理的能力缺口是：**原文条件对应哪个物体、哪些ID仍只是暂定参照、当前观测究竟验证了哪条关系，以及冲突后是否重新检查了上游假设。** 例如“显示器前的纸堆前面两把椅子中左边一把”，只测自选显示器和两把椅子的左右，并没有验证纸堆和椅子组。

这个方向不能简单等同于再加字段或新提示：显式绑定、相机入口、对手比较、局部上下文等已有试验，均未满足采用条件；有的新入口从未被模型调用。测量数值核查也未发现足够常见的算术错误。R109范围反馈的同前缀对照没有引出所需补测，应关闭，不能通过换措辞反复救同一假设。

R117进一步阅读199次数值几何筛查，针对其中32次事件的64项明确数值/排序从实际目录重算，均在声明近似精度内一致；另外167次不能称已认证无误。完整筛查分母、199次原模型响应和限定计算独立复核通过，仍未建立新的复发计算错误。该结果支持暂不新增计算拒绝或强制测量；不证明参照、比较组及方向选择正确。[复核与边界](/Volumes/KESU/datasets/ScanRefer/diagnostics/r117_catalog_calculation_scope_v1/REVIEW.md)

下一项研究应区分“原文关系”与“容易计算的代理条件”：near不自动等于nearest，front不自动等于距离更近，left/right不自动等于世界X大小，独立tile的位置也不代表场景邻接。先定位尚未被现有观察区分的原文条件，再检验一种不同的证据获取或假设更新机制；不要求问题必须是程序违例，也不重复已经失败的字段/反馈变体。先证明确有实际证据与更新，再在冻结的未用ScanRefer样本检验重复收益；稳定收益后做Nr3D回归。GT只在运行后用于评价。

具体优先级是：先检查目标与从句参照是否分清；再检查“哪张桌子周围的哪组椅子”是否选对；最后检查left/right所依赖的观察原点和朝向。几何计算正确不等于以上三个前提正确。应观察模型是否在冲突后重查参照或比较组，而不是只统计它是否多说了理由、多调用了工具。已有开发描述被反复检查，下一批错误发现材料应事先固定新的开发描述、保留全部运行结果，并继续隔离未用验证集；这一步本身不构成提分证据。

视觉数据并非完全缺失：KESU现有original_sensor_v1下有12个非AppleDouble的.sens文件，并有12场景RGB/位姿缓存。它们可核对真实外观与候选可见性，但只是扫描相机视角，不能当作标注者说话视角。已有RGB、局部上下文和相机工具试验未证明稳定收益，暂不据此扩量下载或租GPU。

开发96条中，若Unique仍对19条，约70%需要总对67条，即Multiple从37提升到48/75=64%，净增11条。这是优化量级，不是达到70%的承诺。单个小探针68.75%、观察字段正确或工具调用增加均不构成达标。

保持Multiple不变，即使Unique从19/21提升到21/21，Overall也只有58/96=60.42%。这进一步限定了优化重心。补核SPAZER与IVSGround原文后，“物体可见”与“证据能区分同类候选”的区分仍值得研究；但前者主成绩是250条子集，后者训练了视图选择器，其组件消融主要在Nr3D子集。它们不支持原协议下直接达到70%的承诺，也不构成重试已有RGB/上下文变体的理由。详见[新增原文与迁移限制](/Users/luocl/Desktop/EviGround/docs/scanrefer_evidence_selection_supplement.md)。
