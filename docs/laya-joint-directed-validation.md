# Laya 联合实验定向验收

日期：2026-11-19。独立分支 `codex/laya-dual-process`；所有结果仅是探索记录。

结论：现有服务器上的 Laya 部署可用，真实快慢模型和图片链路已经运行；本轮测试的动作选择合同未通过必要的语义控制，Nr3D 没有最终预测。不能接受该版本为可靠的完整定位流程。这个结论针对已测接口，不是“任何 Laya 提示或架构都不可能成功”。ScanRefer 未启动，未读取定位 GT。

## 分开验证的两类问题

容量使用原来的逐请求保守上界，仍然包含全文、实际图片、Schema 和输出预留，不使用经验比例。完整状态和原始证据继续保存。整合重复系统指令后，旧 v4 的同一拒发请求上界从 39,246 降到 32,754；只说明这一请求可以在原计数假设下认证，不代表后续任意历史都能装下。系统指令合并是行为候选，不能声称数学等价或语义质量不变。

v10 的真实视觉请求预检上界为 21,934；图片实际为 1000×1000，SHA-256 为 `de85c30e9859a740cf229963b149ebf63a902ab075450fa0ab77e4f4fc6c1acb`。返回模型为精确的 `qwen3.8-max`，实际输入 1,664 tokens，其中 image_tokens=963。该决策共享输出预留 2,200+1,500=3,700，低于 4,000。不能把这次 usage 比例用于证明下一请求能容纳。

v10 后续完整状态请求上界为 35,733，在发送前拒绝。原 runner 将它统称 run_budget_exhausted，审计归一化为 capacity_preflight_blocked；实际 B/R/T=1/4/3，没有耗尽样本预算。拒发不是实际模型已超窗的证明。节点映射的离线重放也没有消除所有后续容量问题；不能称容量问题已经全面解决。

## 固定语义测试

测试预先固定六种情形：材质、几何各自的支持／反驳／不足。每种情形交叉证据位置 start/middle/end 和全部六种选项顺序，共 108 次。支持应 commit，缺材质应 inspect，缺几何应 measure，已接受状态与新证据冲突应 consult 请求语义修复。咨询选项只重读无几何的原始分类行，不能产生缺失高度。此测试检查有用动作选择；不执行场景工具，也不代替完整 DagMonitor 验收。

三个候选仅依次改变一个因素，均保留全部合成事实、模型实际选择和完整动作参数：

| 候选 | 唯一变化 | 符合预设动作 |
| --- | --- | --- |
| fixed-v1 | 原完整包装合同 | 24/108 |
| fixed-v2 | 扁平化合同，移除重复固定包装元数据 | 46/108 |
| fixed-v3 | 在 v2 上为每类动作写通用适用条件 | 77/108 |

v3 分情形为：材质支持 18/18、材质不足 8/18、材质反驳 18/18；几何支持 15/18、几何不足 **1/18**、几何反驳 17/18。缺几何时其余选择为 inspect 5、consult 12；没有程序将它们更换成正确测量。相同接受状态仅改变选项顺序的差异保存在 acceptance.json 的 witnesses 中。这些是合成合同符合数，不是 Nr3D 准确率。

全部请求使用 checkpoint 自己的 tokenizer 预检，服务器返回无截断、state_tokens_dropped=0，state/input 计数与预检一致。原合同约 1.1K tokens，远低于 8K；因此这些失败不能归因于隐藏截断。独立的短工单分类阳性对照跨全部排列为 18/18，支持“服务正常但动作合同不可靠”这一有限判断。

## 从头真实运行与修复

v5-v10 每次都重新解析、渲染初始场景、初始化 DAG 和预算，不继承旧预测或节点。每轮仅改变一个因素；旧代码和失败目录不覆盖。

| 版本 | 变化 | 实际停止原因 | B/R/T |
| --- | --- | --- | --- |
| v5 | 合并重复系统指令，状态/Schema/计数器不变 | 非法空 revision_reason 未被原控制器捕获 | 0/1/1 |
| v6 | 将 ValidationError 转为原 ContractFailure 反馈 | 空字段、重复节点；重复失败停止 | 0/6/3 |
| v7 | 补强小图、唯一节点、存在引用、非空原因提示 | 参数重叠、重复选项、重复节点 | 0/6/3 |
| v8 | 共享 Monitor 使用所有动作分支的并集 | 原取 inspect 分支会禁止终审完成；修复后两次目标/参照组重叠 | 0/4/2 |
| v9 | 将模型选择的节点 ID 无损移为对象键 | 本地转换错误错误地假设 ID 枚举仅有一个值，未发送慢推理请求 | 0/4/2 |
| v10 | 支持原多 ID 枚举域 | 一次合法 inspect+真实视觉报告后，后续容量预检拒发 | 1/4/3 |

v8 仍逐个选项按完整原 Schema 验证；并集不允许工具动作提交已完成验证。v9/v10 仅重新编码 ID，解码直接搬回模型给出的 ID，不补节点、不选对象、不更改状态。重复 JSON 键也会被拒绝。12 项离线检查通过，包括错误类型/ID、状态版本、完整参数、实际图片容量、回滚、终审 Schema 和节点映射。

v10 中 Laya 确实在两个模型提议的 inspect 选项之间做出选择，执行桌子 12、13 的场景观察。报告明确保留“透视和遮挡导致高度不确定”，没有将桌子更高、显示器绑定或远左关系补写为完成。全部目标仍活跃，所有节点 pending，没有最终预测或命中率。Qwen 已限制候选并共享 Monitor，因此不能由此证明 Laya 的独立规划增益。
