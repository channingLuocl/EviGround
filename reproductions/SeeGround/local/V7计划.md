# SeeGround v7 计划：语义可执行、几何可用、综合证据选择

状态：v7 首版已实现，行为回归、离线重放和真实 API 小批验证见 `V7验证.md`。完整配对68条和新场景评估尚未完成；以下仍保留原设计目标，不等同于已验证指标。

## 1. 目标与边界

v7 的目标是提高较大范围场景上的整体 grounding 准确率，以接近人的思路利用描述、实例框、颜色和空间关系。允许扫描残缺、类别同义表达和标注瑕疵造成个别错误；依据当前可见输入作合理选择，不为匹配某条标注反向设计规则。

主要行为变化：从“一个必需条件 unknown 就经常不给编号”，改为“综合已有支持与矛盾，能够区分候选时给出最有依据的编号，同时明确哪些条件尚未验证”。暂定答案与已认证答案继续区分。

设计约束：

- 规则按语言结构、物体类别和几何性质定义；场景编号、CSV 行号及标注目标 ID 只用于回归与评估。
- 每个对象的已提供实例框可以作为几何输入；使用框大小不要求再证明扫描完整。扫描风险影响确定性，不自动否决所有尺寸证据。
- 尺寸词和关系的定义保持清楚：面积、体积、实例高度、离地高度分别记录，near 与 nearest 分别处理。
- GT 目标编号、标注同类干扰项列表和浏览器绿/红目标身份不进入推理。
- 保留 v6.2 strict schema、客户端字段校验、自动恢复预算和人工 `--retry-null`，避免推理策略调整混入接口协议回退。
- 按现有模块做局部修改；第一版不引入新的多代理系统、学习排序器或任意手工加权总分。

## 3. 语义解析：把描述变成可以执行的条件

### 3.1 类别归一化与召回

- 已知同义词、复数和分写形式在同一入口归一化，例如 `chalk board/chalkboard/blackboard`。
- 记录原始表达与标准类别，保证后续角色绑定、属性检查、关系取证使用同一映射。
- 对明确的“section/part of + 类别”保留部件语义，并召回母体类别候选；不直接把不存在的 section 当成唯一目标类别，也不立刻退到全场景全部对象。
- 已知映射仍不能召回时，在现有解析/修补流程中让模型结合场景类别表选择合理映射；找不到合理映射时保留未知。避免为每个词另开一次 API 请求。
- 不将不同功能类别一律合并，例如 blackboard 与 whiteboard 的关系应结合描述和场景核实。

验证：同义表达得到一致的合理候选集合；真正不同的类别不会因宽泛字符串匹配被混为一类；候选召回不读取标注答案。

### 3.2 修复否定范围，并执行正反条件

已复现 bug：`The big brown table not the white one` 的 big/brown 被判成 exclude，white 被判成 positive。必须先修复否定的作用范围，避免把目标名词的所有形容词都纳入否定。

- 将条件分成 `big(target, positive)`、`brown(target, positive)`、`white(target, exclude)`。
- 省略表达 one/it 的回指绑定到正确角色，不能把否定的 white table 误设为新参照类别。
- 正向属性和负向属性都要送到外观检查。对白色属性：白色明确成立，违背 not white；白色明确不成立，支持 not white；颜色看不清，继续未知。
- 一个否定条件尚未支持时，其他正向条件继续保留、执行和提供支持。
- 不把“没有看到”直接解释成反面属性成立。颜色、对象不存在、空间关系否定分别处理。

验证：不仅检查解析标签，还检查执行器收到的属性、返回的证据和最终候选变化；覆盖否定前后的形容词、without/except、不同角色及歧义回指。

### 3.3 原子条件、角色与比较范围

- 拆开 `small round`、`big brown` 等复合属性；每个条件保留原文位置、目标/参照角色、正反含义和执行类型。
- spaCy 提供附着提示，结构化解析负责完整条件；两者冲突显式记录，优先用现有修补流程处理，不让错误提示静默删除可用条件。
- 区分“限定候选/比较集合”与“确认最终选择的独立线索”。例如 corner 可以先筛选位置再比较大小；语义不明确时保留两种解释。
- 原始语法解析没有执行器的条件，继续显示为未解决；它不能单独抹去独立的尺寸/颜色证据。

验证：每个条件能追踪到实际取证或明确的未解决原因；不同修饰角色、比较集合和“最大者在角落/角落里的最大者”不混用。

## 4. 几何与外观：使用输入中已经有的证据

### 4.1 按类别和尺寸词使用框度量

第一版采用明确的默认语义，保留来源与适用性检查：

| 条件 | 默认度量 | 特殊情况 |
|---|---|---|
| 普通 taller/shorter/tall/short | 实例框的重力方向高度 dz | 明确说桌面离地高度时才使用 tabletop_height_m |
| 垃圾桶、盒子等立体物体的总体大小 | 实例框体积 dx×dy×dz | 描述明确宽、长或占地时使用对应量 |
| 桌子等的普通大小 | 水平框占地 dx×dy | 明确比较整体体积时保留体积语义 |
| 白板、镜子等薄面物体的大小 | 有依据的板面框面积 | 朝向明确时用板面两个方向；朝向不明记录代理与歧义 |
| 书等可能是单体/一叠的对象 | 结合可见形态选择尺寸代理 | 不把所有 book 一律视为薄板，也不强制以体积解释大小 |

- 已提供且有效的框度量直接可用；点云平面拟合、有向框和稳健边界用于补充或提示冲突。
- 一个点云度量失败，允许使用适用的框度量；不要求全池每个候选都通过额外拟合才进行比较。
- 同一比较尽量使用一致度量与来源；不同来源结果不一致时保留冲突，不混成单一精确值。
- AABB 在斜放物体上可能膨胀；局部接近或代理分歧影响确定性，不能宣称框度量代表精确物理实体。
- small/large 可以依据当前候选和上下文形成相对支持；不声称 small 必然等于唯一 smallest。

验证：测量失败仍能利用有效框；普通高度不被强制替换为桌面高度；类别和方向改变时面积/体积选择合理。

### 4.2 扫描风险和差距门槛

- 扫描不完整、边界离群等风险作为证据质量信息；允许据已有输入输出暂定编号，不为迎合标注排除观测最小/最大者。
- 缺失框、无效尺寸、没有任何可用度量仍不能直接比较。
- 区分“数值存在唯一排序”与“差距足以认证”。重新评估当前比较 10% 门槛和并列 5% 容差，不让微小但唯一的排序只能导致 null。
- 差距很小优先寻求独立线索；预算结束时可给有依据的暂定选择。完全并列且无其他依据时弃答，不靠 ID 顺序破局。

验证：残缺扫描案例可产生带风险的编号；近似并列不被伪装为强结论；度量选择不读取真实目标。

### 4.3 邻近关系与多个参照

- 使用三维框间距、水平间距、物体尺度与共同视角提供邻近支持，避免只依赖投影看起来靠近。
- near/by/next to 形成与场景有关的支持；nearest/farthest 继续执行明确排序。near 不能无条件改写成 nearest。
- 单数描述对应多个合理参照时，评估各绑定，不要求先选出唯一参照才计算关系。
- 多个合理绑定给出同一候选选择时允许汇合；选择分歧时保留歧义，再用其他条件消解。
- 多台相邻显示器可在有上下文依据时作为参照组；集合含义要记录，不能自动把任意同类实例都合成一组。
- 同一几何的中心距离、框间距和渲染图不是独立的三票证据；不要靠重复计数制造高确定性。

验证：所有参照都支持同一选择时不因参照数量而弃答；远处物体即使相对最近也不能自动证明 next to；绑定分歧真实影响确定性。

### 4.4 常见关系执行

优先补 corner 与 on/support，因为已观察到它们频繁阻断现有尺寸描述：

- corner：结合两个相交墙面及实例位置/范围判断，靠一面墙不自动等于处于角落。
- on/support：结合水平覆盖、上下边界和可见支撑给出支持；仅 above 不能证明 on。
- 普通颜色、形状与否定属性共享清晰的检查接口，条件与角色必须真的出现在视觉请求中。
- 跨物体复杂 facing/across from、房间功能、回收标志等先保留未解决与暂定选择，不在第一版为覆盖全部关系创建大量新谓词。

验证：无支撑的悬空物体不被判为 on；靠墙中部不被判为 corner；扩展关系不改变无关颜色/尺寸语义。

## 5. 综合证据与决策：从可用线索走向合理选择

### 5.1 三种输出状态

| 状态 | 何时输出 | 编号/认证 |
|---|---|---|
| 已支持选择 | 当前声明的输入/度量下，必要条件均有支持，且选择可区分 | 有编号；accepted=true |
| 暂定选择 | 有明确尺寸、颜色或关系支持，仍有扫描风险、未解条件或比较歧义；无已验证的致命矛盾 | 有编号；accepted=false |
| 弃答/失败 | 无依据地区分候选、完全并列、相互冲突无法解决、没有候选，或推理进程失败 | null；分别记录原因 |

“已支持”按声明的场景输入和度量判断，不要求认证不可见的完整真实世界。

### 5.2 选择规则

- 保留每个候选在每个条件上的支持、矛盾、未知与证据来源。
- 明确、适用且绑定正确的矛盾可以排除候选；弱支持/近似排序用于选择倾向，不伪造为硬排除。
- 已有单候选兜底与尺寸暂定答案保留，并扩展到有依据的正负外观、关系支持。
- 能按一致度量产生唯一优先候选时允许暂定答案；一个未知候选或未支持条件不自动否决整池。
- 明确违背必要条件的候选不能因尺寸排序领先而获选；未知条件与已证实矛盾分开处理。
- 多条独立线索交叉支持同一候选时加强选择；重复来源不重复计数。不引入未校准的“置信概率”。
- 复核检查具体矛盾；仅提示扫描不完整或尚有 unknown，可以降为暂定，不自动擦掉编号。支持的矛盾继续触发现有回溯。

验证：有支持的暂定答案得以保留；明确颜色/支撑矛盾能够否决尺寸第一名；完全没有证据时不会随意输出 ID。

### 5.3 取证顺序与预算

- 先计算廉价、可直接得到的框度量和关系距离，再把结果交给规划器选择下一步。
- 优先检查最能区分当前候选、且能解除依赖的条件。可以先大小再邻近，也可以先角落再大小，按描述与场景选择。
- 不强制所有关系绑定完成后才允许诊断性尺寸排序；正式子集比较仍须说明集合含义。
- 未检查的关键维度优先于第三次重复检查同一个未知条件。
- 记录工具是否带来新证据；同一测量失败、相同绑定、相同无信息视角不持续消耗预算。
- 第一轮先在现有 3 次工具预算下验证调度；只有验证显示新取证有实际收益，才调整全局预算。

验证：窗户/显示器类案例能取得尺寸证据；重复未知不会吞掉全部预算；平均调用量与长尾延迟一起报告。

## 8. 验证方案与成功标准

### 8.1 离线验证

1. 先复现否定范围和类名映射错误，再以回归测试确认修复。
2. 覆盖候选重排、整体平移、同义改写、正反条件、参照共识/分歧、无信息换视角与零证据案例。选择不应随对象列表顺序变化。
3. 用保存的场景几何与原解析检验测量/决策修改；解析改动需重新解析或用人工解析对照，不能只靠旧解析重放宣称解析改善。
4. 离线重放与 API 真实效果分别报告；所有原有相关协议、恢复、候选排除和复核测试继续运行。

### 8.2 实跑与推广

- 固定模型、温度、上下文上限、并发、工具预算、自动恢复预算与GT/预测类别输入设置，v6.2/v7使用独立目录配对比较。先用开发集小批确认链路，再完整68条。
- 68 条已经人工分析，属于开发集；提升只能说明开发表现改善。
- 现有 `v5_independent_holdout_50.json` 与开发集无重复 CSV 行，但50个场景中24个已在开发集出现。分别报告全部50条、24个重叠场景与26个未重叠场景，不能把全部50条称为场景独立验证。
- 使用 holdout 前核查它此前是否用于调参。要支持“大范围普适提升”，再在未调参的新场景上固定抽样，覆盖尺寸、颜色、否定、支撑、邻近与多参照，并包含非尺寸描述。
- 样本抽取、类别输入设置与参数在看新评估答案前固定。代表场景反馈不能用来预选容易改善的评估样本。
- 对修复解析、框度量/风险策略、关系策略、综合选择/调度做逐阶段对照，避免把所有提升归于某一个模块。
- 保存逐样本转移：null→正确、null→错误、正确→错误、错误→正确与新的失败；检查原32个有编号样本的退化。
- 自动恢复相同；人工反复重跑的累计结果单列，不与单轮基线混报。若 API 波动足以改变结论，再进行配对复跑。

### 8.3 衡量结果

主指标是全部样本的正确率。辅助指标：答案覆盖率、有编号正确率、错误编号数、各类 null 原因、认证/暂定答案表现、API尝试与token消耗、墙钟时间和长尾延迟。

成功标准：

1. 通用行为测试通过，已定位解析错误确实修复；无场景/标注ID特判。
2. 开发集整体正确数改善，并完整披露新增错误和原正确结果退化；只提高覆盖率不能判成功。
3. 未用于调参的更广样本上仍显示净正确数改善；报告按场景配对的变动与不确定性，小样本证据不足时不宣称普适提升。
4. 调用和延迟代价可解释；无需通过无上限重试或一律扩大预算才能得到提升。

计划不承诺一个未经实验的准确率目标；规则是否保留依据配对结果与轨迹证据判断，不能以个别人工案例命中为准。
