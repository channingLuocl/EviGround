# SeeGround v6.2

v6.2 为 OpenAI 兼容接口的生产阶段增加 `response_format.type=json_schema` 和 `strict=true`，并在客户端使用同一份 schema 校验响应。
查询解析、属性补全、规划动作、外观检查、尺寸/关系检查、最终复核及其他结构化视觉复核分别使用对应协议，定义见 `response_schemas.py`。

每个对象都禁止额外字段，所有字段都有明确类型并列为必填；角色、关系、动作和检查结论等使用枚举。
规划动作的可选参数通过 nullable 表达，返回 null 时恢复原有默认处理，不要求模型猜测未使用的编号或相机参数。
最终复核的无关列表返回空数组，不适用的 comparison 和 anchor_id 返回 null。

合法 JSON 仍需通过 schema 和原有业务校验。schema 不证明属性、空间关系或最终选择正确，也不解决接口超时。
接口不支持 schema、返回不合规字段、拒答或截断时记录错误，不自动降级成 json_object，也不剥除代码块后假装成功。
原有单样本传输错误恢复预算保持不变；重试继续使用原 schema，恢复缓存身份包含 schema。

## 本地运行

依赖已加入 `requirements.txt` 和 `requirements-lock.txt`。其他环境先安装：

```bash
.venv/bin/python -m pip install -r local/requirements-lock.txt
```

运行 68 个开发样本：

```bash
local/run_local_v62.sh
```

脚本加载现有 `.env`，开启 `SEEGROUND_V62=1` 和 v4 基础策略，并自动启用 v6 查询结构流程。
workers 与 API concurrency 默认均为 2；已有 `SEEGROUND_WORKERS`、`SEEGROUND_API_CONCURRENCY` 环境配置仍会覆盖默认值。
模型、密钥和接口沿用 `.env`；当前严格协议适用于 `SEEGROUND_API_PROVIDER=openai`，Qwen 原有协议保持不变。
默认创建新的 `local_outputs/v6_2_local_时间戳` 目录，预测记录版本为 `relative-size-v6.2`。

直接使用 Python 入口时，在加载 `.env` 后设置：

```bash
export SEEGROUND_V62=1
export PYTHONPATH=local
.venv/bin/python -u local/run_size_validation.py \
  --manifest local/validation/v5_development_68.json \
  --scene-root local_outputs \
  --output local_outputs/v6_2_dev68 \
  --review-limit 3 --workers 2 --api-concurrency 2
```

v6.1 的旧输出与 v6.2 代码/协议身份不同，应使用新的输出目录。

## 只重跑 null 样本

等当前批次结束或停止后，指定同一个输出目录并加上 `--retry-null`：

```bash
SEEGROUND_RUN_DIR="/Users/luocl/Desktop/seeground/reproductions/SeeGround/local_outputs/v6_2_local_20261013_103813" \
  /Users/luocl/Desktop/seeground/reproductions/SeeGround/local/run_local_v62.sh --retry-null
```

将目录替换为需要重跑的那一批。之后重复执行同一命令，只会重跑该目录中最新结果仍为 `predicted_id=null` 的已完成样本。
已有非 null 编号保持不动，包括答错的编号；尚未运行或尚未写入 `evaluation.json` 的样本跳过，因此这个开关不负责续跑未完成的部分。
不要与使用同一目录的原批次同时运行。

每次手动重跑都会从头推理，使用新的自动恢复预算。原预测、日志和检查点保留；新尝试存到各样本的 `null_retries/attempt_001` 等目录。
样本根目录的 `evaluation.json` 和批次 `results.json` 更新为最新结果，`prediction_path` 和 `log` 指向最新尝试。
原始批次 manifest 保留，重跑配置与样本列表记录在 `null_retry_runs`；汇总的调用量代表最新结果，各次尝试的累计消耗需结合历史日志统计。

该开关同时重跑 API 失败与正常弃答产生的 null；正常弃答不保证重跑后会出现编号。
它与 `--retry-errors` 互斥，后者仍按原有检查点和恢复预算处理显式错误。
复用目录时，推理代码、模型、并发等配置和输入仍必须与原批次一致；仅允许批处理入口自身的代码哈希变化，以兼容增加此开关之前启动的 v6.2 批次。

## 日志与验证

`manifest.json` 记录启用状态和代码哈希；各阶段 `run.json` 记录实际使用的 response_format 与 schema。
schema 校验失败的 diagnostic 包含 `failure_kind=response_schema`、schema_name、validation_error、request_id 和请求摘要。
这些错误不属于可重试的网络故障。

新增离线测试：

```bash
PYTHONPATH=local PYTHONDONTWRITEBYTECODE=1 \
  .venv/bin/python -m unittest local.test_v62_structured_outputs
```

测试覆盖严格参数传递、必填字段/类型/枚举/额外字段、空理由、拒答/截断、禁止静默降级、传输重试、缓存隔离及可空规划参数的默认行为。

协议参考：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。
