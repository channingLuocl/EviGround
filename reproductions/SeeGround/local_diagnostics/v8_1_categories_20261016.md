## 原因证据

- 原始 v8.0 有 0 个 API 错误；原始响应 usage 包含图像 tokens，图片已发送。
- mini fridge、window、computer tower 三个严重错例逐点包围盒与 GT OLT 最大误差均小于
  0.000001 米，没有发现实例 ID／点云错位。
- 原图每个物体只占 512 像素格的一小部分，半径 1 像素的稀疏十字点导致表面和轮廓断裂。
- 只调整取景、点圆盘与多图输入的固定 12 个样本仍为 3/12，不能把成像假说当作完整解释。
- 原始表面连接、场景上下文、尺寸／离地高度共同改善识别；例如 scene0565_00 #31
  从 chair 改为 window，但 mini fridge 仍识别为 cabinet，说明分类能力与类别粒度仍有问题。
- chair/office chair、table/desk、plant/potted plant 等近义／上下位类别仍按原规则区分，
  未通过修改评分把错误改成正确。

## 实现范围

1. 三个孤立视角按投影点覆盖选取，保持 90 度间隔并自动取景。
2. 优先读取原始 ScanNet 三角面，核对顶点顺序、轴对齐坐标与 RGB 后深度渲染；
   仅在实测三角面内插值颜色，不补全缺失几何。没有网格时记录点圆盘回退模式。
3. 上下文扩大并从房间内部方向观察；输入实测尺寸、估计离地高度。
4. 请求发送四张独立图片，拼图仅供人工审查；schema 用共享类别定义减少重复枚举。
5. 修复提前停止时尚未开始的场景目录不存在导致汇总导出失败的问题。
   验证过程仅迁移过这一项非推理改动的检查点哈希，旧 config 与说明均保存。

GT 类别、作者类别和查询不进入推理。网格模式额外使用原始面连接，不能声称严格只有点坐标输入。
v7 定位器和共享 API 客户端均未修改。
