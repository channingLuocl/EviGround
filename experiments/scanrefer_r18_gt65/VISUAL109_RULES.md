# Visual109 v1 — 固定规则、独立一轮、手动启动

基线：`outputs/r18-null-visual-recall-v1/results.json`，9508 条，Acc@0.25 = 6108/9508。
选择：仅该版本 383 条补跑中的全部 109 条 Acc@0.25 失败，不扩至其他失败。
这是使用评估结果选取和分析的开发子集；独立输出不意味着独立测试集。

## 推理规则（所有选中样本相同）

1. 允许所有分类器覆盖实例；非空类别池也不再硬排除其他实例。
   Top-5 名称、分数、排序保持原值，只作为先验。补充几何实例不进入目标池。
2. 保留原三张场景图。按实例 ID 升序生成全候选图册：固定 315°/30°、
   每实例 300px、点半径 2px、每页最多 12 个、4 列，不显示类别答案。
   图册为独立缩放的 RGB 点云观察；页序、格子位置与尺寸没有空间含义。
3. 依据完整原句区分所指目标、参照物、支撑物、附属物与部件/整体。
   不采用首名词或末名词规则；解析器可以被原句和观察纠正。
4. 用动态 inspect 比较拟选目标、最强合理对手和必要参照物；依据判别条件
   选择 isolated / scene / measure。最终证据说明目标名词短语、参照 ID、
   对手和判别子句。图册不算动态聚焦检查。
5. 最多 3 次动态证据动作，inspect 和 measure 的 focus_ids 上限均为 12。
   提前 finish 而未动态检查拟选目标时，在有预算时退回检查；预算耗尽时
   如仍选未经检查对象，原有机制保留选择并明确记录 unresolved。
   不伪造额外动作或延长预算，保留 abstention。
6. API 保持严格单个顶层 JSON 对象契约及原格式恢复预算；不把错误数组
   猜成答案，不按 GT 修复响应。

## 资源与合并

新增固定资源为 N 个实例渲染、ceil(N/12) 张图册和原来的全部 3 张场景图。
每步保留既有图像，所以图像请求和 token 成本可能增加；不能视为同资源对照。
动态工具上限仍为 3，每次 inspect 原有最多两组 6 实例渲染保持不变。
实际资源、模型请求、token 和耗时分别记录；不预估费用或承诺提升。

每条仅一轮新轨迹；正确、错误、弃答、异常均等缓存。
全部 109 个新结果必须一次替换，保留其他 9399 条，不按新旧正确性择优。
输出是跨版本级联系统的累计结果，不能报告为全量单次或独立测试准确率。
选择清单和 GT 仅用于父进程评估；子进程仅接收场景、原句、输出位置、
Top-5 和动作预算，不接收目标 ID、IoU、历史结果或本次分析报告。

prepare/preflight 不调用模型。完成后再次 run 只报告；不启动第二轮。
中断且没有 prediction/evaluation 的轨迹要求审计恢复，不静默重新抽样。
代码、规则、输入和基线的哈希在 protocol.json 冻结，变更会阻止启动。

手动入口：

```bash
cd /Volumes/KESU/experiments/scanrefer_r18_gt65
bash retry_visual109.sh preflight
bash retry_visual109.sh run
```
